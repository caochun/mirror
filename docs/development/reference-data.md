# 参考 Excel 的演示初始化数据

根目录 `当前测试库样例数据_脱敏_20260923.xlsx` 包含说明，以及人员、标签、人员标签、推送任务、推送接收人五类各15条样本。它是抽样参考，不是完整可迁移数据库，也不决定 Domain Pack 的结构。

当前生成的数据位于 [reference-personnel.json](../../src/main/resources/demo/reference-personnel.json)，由 [ReferenceDemoData](../../src/main/java/gov/mirror/app/ReferenceDemoData.java) 加载。运行不依赖 Excel 文件或 Excel 解析库。

## 数据范围

| 对象 | 新增数量 | 参考与合成方式 |
| --- | --- | --- |
| Person | 15 | 使用“演示人员001–015”；参考性别和职级，身份证、出生日期等缺失项不补造 |
| Organization | 18 | 参考所属单位路径拆分层次，单位名中的“昆山”替换为“示例”；路径层次为演示建模，不宣称权威组织结构 |
| Position / Appointment | 10 / 15 | 相同岗位名合并为岗位定义，为每人建立独立任职；不把“一把手”等描述直接推导成标签，不伪造任职开始日期 |
| ExternalIdentity | 15 | 使用合成来源与引用，记录样本 ACTIVE/INACTIVE；不填已核实时间，不当作真实外部身份 |
| ObjectMembership | 15 | 明确合成10已纳入、3待准入、1暂停、1排除的场景；不从来源同步状态推导 |
| Tag / TagVersion | 22 / 22 | 参考15条标签样本，另按父标签代号和名称补齐7个父节点；启用状态参考样本，版本为合成发布快照 |
| PersonTag / TagContribution | 7 / 7 | 人为配置完整的演示关联与人工依据，明确标注“非 Excel 原人员标签关联” |

新增数据使用 `ref-` 身份空间；PersonTag 使用现有业务服务相同的人员/标签规范关联键。原有两家基础示范单位和一个标签仍保留，因此开启两套演示数据后共有20个组织、23个标签。

## 可查看的场景

| 人员 | 场景 |
| --- | --- |
| 演示人员001 | 已准入、人工依据有效，标签当前生效 |
| 演示人员002 | 标签目录项停用，保留依据但不生效 |
| 演示人员003 | 人工取消标签生效，依据保留，可通过追加人工依据明确恢复 |
| 演示人员004、006、010 | 待准入，不能赋标 |
| 演示人员005 | 准入暂停，标签依据保留但不生效 |
| 演示人员007 | 合成来源停用与准入状态独立；用于观察不同事实，不代表正式来源治理规则 |
| 演示人员008 | 贡献已结束，标签不生效 |
| 演示人员015 | 人员已排除，保留标签依据 |

所有初始化对象的技术历史记录真实写入时间。发布、准入、贡献等业务时间为初始化时生成的演示时间，不复制 Excel 时间冒充历史变更。状态是合成快照，不声称已经执行过真实准入审核、规则计算或标签工作流。

## 启用方式

```bash
python3 scripts/run-mirror.py --build --init-local --reference-data
```

已有构建和本地账号时：

```bash
python3 scripts/run-mirror.py --reference-data
```

对应配置是 `mirror.foundry.seed-demo=true` 和 `mirror.foundry.seed-reference=true`。参考数据开关默认关闭，单独开启而未启用演示模式时启动会拒绝。也可将第二个属性写入本地 `application.properties`，让后续启动持续检查初始化回执。

以 `admin` 登录查看全部样本。原 editor/reader/other 账号的组织授权不自动扩大；若需某账号操作样本，应在本地账号配置中明确授予对应组织 ID。不能因为它们是 mock 数据就绕过授权。

## 重启与已有数据

整个参考数据集在一个事务中创建，并同事务写入 BOOTSTRAP 审计和带数据摘要的初始化回执。不会生成假的 Action 完成事件，也不会启动任何发送或规则任务。

重复启动看到回执后直接跳过，不重置用户后续修改。没有回执但发生对象 ID 冲突时整体回滚，不覆盖现有数据；任何中途关系错误也整体回滚。同一 datasetId 对应的资源内容改变时拒绝重新初始化，后续升级须显式设计数据迁移，不通过改版本号自动覆盖。

初始化成功后，即使下一次启动不传 `--reference-data`，数据仍保留。该开关不是清空或重置功能。

## 未直接导入的样本

Excel 的人员标签涉及人员表之外的 P016/P017 等代号，接收人也引用了更多未提供档案的人员。P004 在人员表与接收快照中的单位不同，不能据此覆盖当前归属；某些送达成功行仍有失败分类，不能直接推断当前业务状态。

因此本轮没有直接搬入人员标签关系、推送任务和接收人。推送状态还需分解成提醒生命周期、审核、发布、投递、撤回、阅读等独立事实，正文与批准证据也未提供；后续提醒页面可参考这些状态设计明确的合成场景，不推导真实审批、阅读或投递事实。

政治面貌、工作领域、单位性质和职务层次等列没有为了导入而新增本体字段，也没有偷放入未定义 JSON。标签表的 `RULE_ONLY` 仅作为来源参考，不意味着 Mirror 已实现对应自动规则或正式赋标方式管控。
