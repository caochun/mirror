# Foundry持久幂等与故障恢复

日期：2026-09-28。Foundry提交：`66bf71dc4c0d71e388a3688c1486c4ad28333183`。完整覆盖上游目标仍在进行，本次完成数据库命令回执阶段。

## 改动

Storage SPI新增事务读写命令回执和事务内对象/关系读取。JDBC把回执与业务、历史、审计和outbox一次提交，内存Provider则把回执纳入同一状态快照。ActionExecutor优先使用Provider能力，跨Executor实例不再依赖进程内缓存。

幂等键按租户、主体、动作隔离并绑定请求/配置摘要；重放返回原结果，重新检查权限，不重复执行已成功的前置条件和效果。等待数据库锁后再次授权；关系删除权限检查使用事务连接，支持单连接池。内存乐观冲突有界重试，数据库回执未知/损坏时不重新执行。

JDBC写事务明确采用READ_COMMITTED，保证等待租户锁后看到前一个提交者的结果。多效果更新同一实体使用事务内最新版本；表达式仍读取执行前捕获的参数。

Foundry完整122项、Mirror完整232项测试通过。新增12项持久回执和API测试，覆盖文件库重启、12次并发请求、两独立JVM竞争、实际提交前/后进程退出、回执写入故障、参数冲突、撤权、条件失败、坏回执、同对象多效果、单连接池等。
