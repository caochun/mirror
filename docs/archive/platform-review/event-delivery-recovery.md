# Foundry事件领取与消费恢复

日期：2026-09-28。Foundry提交：`6e2e400`。完整上游核心覆盖目标继续。

## 已实现与修复

Outbox新增持久租约、领取token、续租、失败退避与受token保护的完成确认。工作进程退出后可在租约到期时接管，旧工作线程不能确认或释放新一轮领取。JDBC租约使用附属表，原事务生产者及事件payload不用改写；投递回调不占数据库连接。

消费去重改为成功回调后的完成回执。作用域包含consumer、tenant、CloudEvents source和id，并绑定内容摘要。正在执行时不能向调用方假报成功，回调失败可重试，进程退出后可接管。修复原内存sink记住失败事件，以及原JDBC在回调前写“已消费”造成永久漏投的问题。

旧已消费表无法证明回调完成，新版默认要求明确的迁移判定，不自动猜测成功或重放。可信迁移代码可确认已有外部成功证据，或明确允许可能重复的执行；运行库本次没有迁移。

事件数据改为深度不可变JSON值，允许可选null字段。Mirror回归暴露业务命令把Java页面record嵌入事件：已改用同一命令生成的JSON响应值，保持返回、回执与事件内容一致，没有放宽底座边界。

## 验证

最终 `mvn -q test`：根reactor321项，其中Foundry211项，均无失败/错误/跳过。本阶段新增23项测试，包括memory/H2租约一致性、并发、续租、租户和消费者隔离、失败重试、不可变payload与旧凭证失效。

独立JVM在outbox领取后、消费领取后/回调前及回调后/完成确认前强制退出，重建后均可恢复。两个独立JVM经本地H2 TCP竞争一条事件，只有一个有效领取者。真实事务outbox生产者、完成回执和确认故障组合测试覆盖回滚、单连接池、较高默认隔离级别及非自动提交连接。

独立探针新增消费失败可重试及完成后重复抑制证据，既有属性、时间、导航、Action等修复保持通过。H2、受控时钟和本地回调不等于真实国产库或外部投递平台验收。

## 边界与下一步

保证是至少一次：外部回调已经生效但进程尚未记录完成就退出，可能重复投递；应把稳定事件ID传给接收方做幂等。当前在每条回调前续租，回调期间没有自动后台续租，需匹配处理超时与租约。

Action.sideEffects、持久副作用任务、webhook、失败策略及ROLLBACK_ALL补偿尚未完成，BorrowBook和完整Library借还仍未通过。下一步把本阶段的恢复基础接入这些流程。死信/运维查询、大队列性能与实际目标库验证也仍在计划内。
