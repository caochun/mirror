# Foundry本体权限目标与真实OpenFGA验证

日期：2026-09-28。Foundry提交：`3473b4b`。原始上游仍固定为v0.3.0 / `1d7e1aa`，完整覆盖目标继续。

## 本次改动

新增可信启动配置`ONTOLOGY_TARGETS`：按ODL定义选择首个对象参数作为动作权限目标，其余参与对象检查viewer；额外修改已有对象在属性校验及写入前检查editor。关系通过端点权限控制，不再要求原模型不存在的Member.can_borrow/can_return或LinkType.can_*。

服务端记录实际变更类型，区分本动作创建的对象与其他已有对象。新建实体无需预置不存在的资源元组，后续效果、幂等重放和任务恢复均按原变更记录复核当前授权；这不授予新对象的通用读取权。提交前仍统一复核，拒绝会回滚全部业务及历史。

旧默认构造器保持STRICT_RESOURCES及独立关系ACL。新模式需要显式启用；无对象参数的动作仍要求ActionType上的明确授权。旧回执缺少创建证明时采取保守检查，损坏证明不会触发重新执行。

OpenFGA客户端新增与上游一致的snake_case类型映射，继续保留租户限定ID。启动时读取指定服务模型并验证所需关系，Check采用HIGHER_CONSISTENCY且只接受布尔true。类型映射碰撞、缺失关系、错误响应均拒绝。

## 验证证据

常规 `mvn -q test`：Mirror根reactor378项，其中Foundry268项，全部通过，无失败/错误/跳过。新增17项普通测试覆盖主目标/集合、参与者、额外编辑、创建证明、旧与损坏回执、类型别名及响应边界。

另有 **9项真实OpenFGA集成测试**全部通过。使用官方OpenFGA 1.21.0、隔离loopback内存实例；原Library权限DSL由官方syntax-transformer 0.2.2转换，没有给Member或关系类型补造can_*。测试在memory和H2单连接池下验证借还、关系读取/历史、撤权后的重放拒绝、删除失败的整笔回滚、相同本地ID跨租户隔离，以及模型启动门禁。

新测试通过独立profile执行，普通构建不执行IT，显式启用但缺少服务会失败。测试结束后服务中的store列表为空，临时服务已关闭。配置命令、版本、SHA及模型来源见[集成说明](../../../foundry/spec/openfga-integration.md)。独立审计探针也已改为仅允许原模型声明的关系，并通过借还流程。

## 边界与后续

本次证明真实OpenFGA关系模型可工作，没有将手工构造的测试主体当成OIDC端到端认证。生产服务凭据、权限/字段关系文件自动装配、元组生命周期和实际国产库仍需继续验证。新模式比上游更严格地保护参与对象与额外编辑目标；切换旧部署时须按新类型名配置元组，不能只替换模型文件。

其余ODL/Pack组合、计算字段、类型化API、查询、注册表、同步和运维缺口继续保留。详见[ADR-0013](../../../foundry/spec/adr/0013-ontology-authorization-targets.md)及[总计划](../../../foundry/spec/upstream-parity-plan.md)。未重建运行中的Mirror JAR或改动实际业务数据库。
