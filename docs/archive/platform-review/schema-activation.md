# Foundry模型激活与写入门禁

日期：2026-09-28。Foundry提交：`4d554c4`。完整核心覆盖目标继续。

## 本阶段

JDBC把候选登记与当前激活版本分开。普通applySchema只负责首次采用或连接相同模型；模型变化须显式activateSchema并指定预期激活版本，破坏性变化须有已批准计划。

切换前校验所有租户的当前对象、关系、必填/类型/枚举/CEL、唯一性、端点和基数。不会借默认值或readonly生成器补造已有事实。已验证“先加可选字段、回填、再收紧为必填”的迁移流程。

写事务捕获不可变模型绑定，在变更前和提交时检查持久激活身份。提交门禁短暂锁住active行；激活冻结提交并检查已提交数据，切换后的旧事务整体回滚。不同租户可以并行执行未提交变更，未采用全事务全库独占锁。模型登记追加、激活日志与active指针同事务提交。

对象/关系、命令回执、Action执行、审计和outbox均受写入门禁约束。旧实例经JDK HTTP写入返回409 / SCHEMA_VERSION_MISMATCH / retryable=false，宿主重新装配后可继续。恢复已结束关系时，也会检查其端点是否仍符合当前模型。

## 验证

常规根reactor **544项**，其中Foundry **434项**，全部通过，无失败/错误/跳过。新增15项覆盖激活与候选分离、存量校验、迁移步骤、竞争/返回旧模型、在途回滚、全部写入口、不同租户并行、首次旧数据采用、失败回滚、HTTP和独立JVM恢复/旧进程拒写。

独立探针确认候选登记不切换模型、旧实例和在途提交被拒绝、未提交对象不存在，已批准但缺失必填数据的激活仍失败且版本不前进。激活物理提交前后进程退出也验证了模型登记、激活记录与指针的一致恢复。

## 边界与下一步

公共读SPI及已经构造的ApplicationService尚未绑定activation_id，不能把本阶段理解为完整的模型/字段策略热切换治理。读请求和应用装配的版本绑定是下一重点。

内存仍使用本地revision机制；原始SQL及旧构建不会自动遵循新门禁，升级采用前须停止这些写入。初始物理DDL独立完成，本阶段没有实际生产库迁移、自动类型转换或批量回填执行器。真实目标数据库、物理漂移与性能仍待验收。

运行中的Mirror JAR和业务库未改动。完整契约和升级说明见[ADR-0022](../../../foundry/spec/adr/0022-schema-activation-and-write-fence.md)。
