# Foundry持久Schema Registry

日期：2026-09-28。Foundry提交：`e4e1f08`。完整核心覆盖目标继续。

## 本阶段

新增JdbcSchemaRegistry，持久保存完整模型版本、diff、分类、登记时间和MigrationPlan说明/批准标志。与内存实现共用登记契约，支持历史版本读取、原子expectedVersion检查、启动applyIfChanged去重和requireCurrent配置漂移校验。

并发控制使用数据库行锁；快照和当前版本指针同事务提交。读取检查版本连续性、格式、校验和、模型指纹和头指针一致性，损坏或不支持的历史明确拒绝。

新注册表指纹保留Action参数顺序，修复用旧编译摘要判断模型等价时可能漏掉权限主目标变化的问题；原编译摘要和命令回执格式保留。namespace变化新增BREAKING分类，声明version变化纳入元数据diff。破坏性登记没有明确批准的计划会拒绝，过期预期版本不能覆盖新记录。

## 验证

常规根reactor **529项**，其中Foundry **419项**，全部通过，无失败/错误/跳过。新增17项覆盖内存/JDBC契约、完整声明回读、文件恢复、范围隔离、单连接池及非自动提交、并发去重/CAS、损坏拒绝、头更新失败回滚，以及独立JVM竞争和物理提交前后退出。

独立探针确认重建后相同配置仍为版本1，Action顺序漂移/未批准变更拒绝，批准登记为版本2，旧预期版本拒绝，旧模型及审批说明完整保留。运行中的服务JAR和业务库未改动。

## 尚未覆盖

**登记成功不代表数据迁移完成。** 当前MigrationPlan记录治理说明，不执行DDL、数据回填或存量约束验证。JdbcStorageProvider.applySchema及在途写入尚未绑定持久注册表，requireCurrent仅是调用时检查，不能阻止随后发生的模型变化。

存储激活与写入版本门禁是下一重点；生产启动装配、实际迁移执行、物理模式漂移、审批权限及实际目标数据库验收仍待完成。详见[ADR-0021](../../../foundry/spec/adr/0021-persistent-schema-registry.md)。
