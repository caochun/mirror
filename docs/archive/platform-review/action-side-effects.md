# Foundry持久副作用、恢复与本地补偿

日期：2026-09-28。Foundry提交：`3dad99f`。上游基线v0.3.0 / `1d7e1aa`。完整核心覆盖目标仍在进行。

## 本次实现

业务effect、解析后的副作用任务、补偿依据和执行回执同事务提交；提交后才调用事件或webhook处理器。任务使用持久状态、领取token和下一次可处理时间，进程退出可接管，同一幂等键不会重做业务修改。Java与HTTP提供续执行入口，重新检查当前主体及权限。

三种失败策略均接通：LOG_AND_CONTINUE记录警告并继续；RETRY_INDEFINITELY持久等待重试；ROLLBACK_ALL进入本地补偿。等待返回PENDING/RUNNING，批量结果单独计pending，不能把它们误认为已完成或最终失败。

补偿逆序执行并检查动作最后写入版本。对象恢复保留字段缺失/null差异；创建对象若后来出现其他关联则拒绝删除；关系用原ID追加RESTORED事实，历史投影正确区分新的生命周期。遇到第三方写入、关联或约束冲突时整组补偿回滚并报告COMPENSATION_FAILED，不覆盖后续数据。

支持上游省略target的createObject生成ID及后续类型名引用。事件携带解析后的数据、稳定幂等标识、原始时间和业务事务ID；webhook限制到可信配置允许的端点，禁用自动重定向，携带固定Idempotency-Key。没有对应处理器时，业务写入前即拒绝动作。

## 验证

最终根工程 `mvn -q test` 共361项，其中Foundry251项，全部通过，无失败/错误/跳过。本阶段新增40项，包括28项memory/H2工作流测试、5项独立进程测试、3项事件/HTTP处理器测试、执行记录故障原子性测试、2项上游Library流程测试，以及HTTP恢复权限测试。随后共享工作流28项补查在途RUNNING重放仍通过。

独立JVM分别在业务提交后、回调后、补偿提交前/后强制退出，恢复后业务修改与补偿不重复。两个JVM共享同一原业务执行与有效任务领取；过期旧回调的失败不能回滚新工作线程已经完成的动作。任务落库失败不会留下部分业务、历史或回执。

原始core/library manifest、ODL、BorrowBook和ReturnBook通过借书、一次解析后事件、同键重放、还书，以及默认三次通知失败后的补偿。JDBC使用单连接池验证回调不占原业务连接。独立探针也在memory/H2运行了原始借还。旧无副作用manifest的默认及显式失败策略指纹对照6e2e400实现核验，原回执保持兼容。

## 已知边界及下一步

Library测试使用受控授权，并显式初始化原始目录数据。现有Java API对所有引用使用同一can_*关系，但上游Library的Member未声明can_borrow/can_return；这是真实权限模型的已知映射差异，下一阶段需修正。没有将受控测试冒充原FGA文件或真实身份服务已可直接使用。

外部投递仍是至少一次，已经送达的外部通知不能由本地补偿撤回。未知结果后的重试使用同一幂等标识，接收方需去重。宿主需要配置恢复调度；改变定义会拒绝旧任务恢复，部署须保留原定义。生产运维修复、自动续租及真实事件总线/国产库仍需验证。

跨Pack组合、权限/种子自动装配、完整ODL、类型化API、查询、注册表和同步等缺口继续保留。详见[ADR-0012](../../../foundry/spec/adr/0012-durable-action-side-effects.md)和[总计划](../../../foundry/spec/upstream-parity-plan.md)。本次未扩展Mirror业务、重新打包运行服务或迁移实际业务数据库。
