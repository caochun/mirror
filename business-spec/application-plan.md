# 基于 Domain Pack 的完整系统实施计划

当前目标：重新验证Domain Pack对两份原始文档的业务覆盖，通过后基于Pack实现完整系统，包括Dashboard。原“大屏价值验证”计划归档于archive/，不再限定当前范围。

## 已完成的定义复核

见 [domain-pack-review.md](domain-pack-review.md)。Pack0.2.1补齐人工恢复、未知重试与迟到回执、进行中撤回和审计读取契约；在记录的范围假设下通过定义层复核。生产能力仍逐项验收。

## 实施顺序

1. **契约驱动的基础写入**：运行时读取Pack动作/状态，明确已接通处理器；人员资格、标签贡献/抑制、版本和关系历史；拒绝未知或尚未实现动作。
2. **数据治理与标签工作**：人员/组织/任职来源接入、关联异常、映射与规则预览/发布/局部重算、AI建议复核、批次、专项事项和阶段。
3. **内容与提醒**：受控媒体和富文本、内容示例、选人条件与手工排除、确认摘要、冻结快照、本级独立审核、定时过期/取消。
4. **送达与本人阅读**：持久作业、鹿路通适配与故障Mock、回执幂等与乱序、独立H5、修订不延长期限、逾期与逐人撤回。
5. **业务统计和Dashboard**：从上述稳定对象/关系/事件聚合，按组织权限和时间筛选、明细下钻；Mock只作为显式演示模式，不能混入真实统计。
6. **AI助手及交付**：受限查询、口径依据、动作卡进入人工向导；完整权限/审计、重启/重试恢复、国产库和真实外部契约联调、性能与部署。

前端继续React + Tailwind，由后端HTTP同源提供；Foundry保持独立子模块。正常四空格Java代码、合理换行，禁止压缩式生成代码和无关全仓重排。

## 实现规则

- 每个已接通动作明确声明对应的Pack契约、处理器、参数适配和测试证据。声明不是执行器，禁止空effects伪装实现。
- 保留现有运行数据和未完成工作；涉及旧数据语义时显式迁移/标记遗留，不使用当前配置伪造旧快照。
- 真实身份/组织权限来自服务端；前端筛选不能替代写入时逐人验权。
- 外部发送只从已提交作业/outbox触发；Mock、真实渠道和真实模型的证据分开记录。
- 业务验收、API/浏览器、持久化、权限和性能证据满足后才勾选；不能因Maven构建或指标静态展示成功就宣布完整。

当前完整goal保持active；继续按上述顺序实现，不以原大屏完成状态结束目标。
