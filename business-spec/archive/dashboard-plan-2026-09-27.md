# 政务对象库核心价值大屏计划

用户已将建设目标调整为：先验证政务对象库的核心业务价值，不继续实现完整的生产业务系统。前端继续采用 React + Tailwind，数据允许使用明确标注的 Mock 数据。

## 要验证的核心价值

大屏只回答五个问题：

1. **对象是否完整**：全市有多少有效人员、多少已停用、多少身份或组织关联异常。
2. **关系是否清楚**：人员当前归属、组织层级和重点单位分布是否清晰。
3. **画像是否形成**：人员标签覆盖率、长期性与阶段性标签分布、没有形成画像的人员规模。
4. **提醒是否精准**：提醒任务覆盖哪些组织和标签，目标人数、送达率、阅读率和逾期人数如何。
5. **闭环是否可追溯**：从人员、标签到提醒、送达、阅读和逾期，是否能回到具体对象和时间。

## 交付形态

- 一个由 Spring Boot HTTP 服务提供的 React + Tailwind 大屏页面。
- 页面使用 `web/src/dashboardMock.ts` 中的脱敏演示数据，并在页面固定显示“演示数据 / Mock”标识。
- 大屏可以直接展示，不要求先登录真实账号；后续接入真实 API 时保留相同的数据投影结构。
- 保留现有人员目录和标签页面作为辅助验证入口，不继续扩展完整提醒审核、鹿路通生产对接和 AI 执行链路。

## 大屏分区

| 分区 | 展示内容 | 业务价值 |
| --- | --- | --- |
| 总览指标 | 有效对象、标签覆盖、提醒任务、阅读率、逾期未读 | 说明对象库是否产生整体管理价值 |
| 对象与组织 | 组织树摘要、单位人数、关联异常、非对象账号 | 说明对象和关系是否可管理 |
| 标签画像 | 因人/因事覆盖、重点标签排行、无标签人数 | 说明是否从人员底数形成可解释画像 |
| 提醒闭环 | 目标、提交、送达、已读、逾期漏斗和趋势 | 说明是否形成精准提醒闭环 |
| 数据质量 | 身份缺失、组织冲突、档案未关联、标签规则无法计算 | 说明数据底座能否暴露治理问题 |
| 追溯入口 | 最近任务、重点标签、逾期单位、时间范围 | 说明统计不是孤立数字，可以下钻到对象 |

## 明确不在本轮实现

- 完整人员主数据同步和生产账号体系；
- 完整标签规则、AI批次和规则重算后台；
- 内容审核、定时发送、修订撤回等生产任务链路；
- 鹿路通真实契约、外网 H5 身份和正式回执；
- 国产数据库生产联调和 5 万级真实性能验收。

这些能力保留在历史规约中作为后续方向，但不再作为本轮大屏完成条件。

## 完成门槛

- 页面由后端 HTTP 服务直接提供，不依赖单独的 Vite 服务；
- 首屏在桌面宽度展示完整价值链，窄屏不出现横向溢出；
- 所有 Mock 指标显示统计时间和数据标识；
- 关键指标之间口径一致，例如标签覆盖人数不能超过有效对象数，阅读率分子不超过送达人数；
- 至少有一条从“逾期未读单位”进入人员/任务明细的演示路径；
- 前端生产构建通过，页面截图和浏览器测试可复现；
- 文档、任务清单和 README 不再把完整业务系统描述为本轮目标。
