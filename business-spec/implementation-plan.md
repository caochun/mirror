# Mirror 业务系统实施计划

本计划把 `business-spec/` 中的业务需求拆成可以在 Foundry 上持续验收的交付阶段。每一阶段都必须有对象模型、受控 Action 或业务服务、历史/审计验证和自动化测试；阶段完成后才进入下一阶段。

## 阶段 0：工程基线

- 保持 Foundry 为独立 Git submodule，不把政务语义放入 Foundry。
- 以 `domain-pack/` 作为全新业务包，命名空间固定为 `gov.object-library`。
- 根 Maven 工程能够构建 Foundry、业务服务和验证测试。
- 删除旧 `gov-supervision-pack` 的引用，冻结业务术语和状态词表。

验收：`mvn test` 通过，Domain Pack Loader 能加载对象、关系和 Action，工作区不再依赖旧业务包。

## 阶段 1：基础对象域

- 实现人员、组织、岗位、任职、外部身份和关联异常的登记服务。
- 用 Foundry 关系表达当前组织、岗位和任职历史；调动通过事务 Action 完成。
- 实现停用、重新启用、非对象账号和关联异常处理。
- 对当前组织唯一、停用人员保留历史、异常人员禁止进入业务名单等不变量进行测试。

验收：人员登记、组织变更、调动、停用/启用和异常处理均产生对象历史、关系历史、审计和事件。

## 阶段 2：标签域

- 实现标签目录、版本、规则、人员标签、候选、批次和处理异常。
- 支持确定性规则、人工赋标/删除/恢复、AI 候选复核和局部重算。
- 保存来源、版本、生效区间、操作人和抑制状态，保证规则失效不删除其他来源标签。

验收：同一人员可以有多个来源的标签记录；人工删除能抑制规则重新赋标；所有状态转换可按版本和时间查询。

## 阶段 3：提醒内容和任务域

- 实现内容示例、内容版本、媒体、提醒任务、任务版本和接收名单。
- 支持按组织/标签/指定人员生成名单，冻结审核快照，提交、审核、驳回、过期和取消。
- 支持立即发送、单次定时发送、修订和撤回；已发布任务使用独立版本快照。

验收：示例修改不影响已发布任务；名单冻结后不可静默变化；每个状态转换都有审计和幂等键。

## 阶段 4：送达、阅读和逾期域

- 定义鹿路通 Connector 接口和内存 Mock 实现。
- 实现逐人送达尝试、成功/失败/未知结果、失败重试和送达回执。
- 实现当前任务版本首次阅读、阅读时限、逾期记录和解除。
- 计算送达率、阅读率、逾期率和异常率。

验收：只有送达成功才启动阅读计时；重试成功重新计算起算时间；重复回执不会生成重复业务结果。

## 阶段 5：权限、统计和 AI 助手

- 配置超级管理员、片区管理员、单位管理员和审核员的数据范围。
- 验证当前组织上下文和组织树范围的越权拒绝，并记录敏感字段查看审计。
- 提供面向 AI 的只读查询和需要人工确认的动作卡，禁止模型直接发送提醒。

验收：跨组织读取和写入按角色拒绝；AI 查询可返回来源和时间；动作卡确认后才执行 Foundry Action。

## 阶段 6：交付验证

- 使用脱敏样例完成基础对象、标签、任务、回执和历史端到端场景。
- 运行内存 Provider 和目标国产关系库方言的共享一致性测试。
- 完成 5 万级分页查询、幂等、失败重试、审计和部署配置验证。
- 更新 `business-spec/tasks.md`，每个任务关联代码、测试和验收结果。

## 当前迭代顺序

1. 提交阶段 0 的 Maven 聚合工程和基础验证。
2. 建立 `business-core` 模块，完成阶段 1 的基础对象服务和测试。
3. 在同一服务中加入标签 Action 和历史测试。
4. 加入提醒任务、Connector、回执和统计服务。
5. 最后补齐权限、AI 查询和目标数据库验证。
