# 完整应用持续开发记录

## 2026-09-27：Domain Pack 业务定义补全（未恢复完整系统开发）

用户要求覆盖两份原始DOCX的业务要求，同时不照搬其中的技术方案。本次仅修改Pack定义与定义验证，不启动服务、不执行数据库迁移、不改暂停中的业务处理器。

- 定义版本升为0.2.0：51个对象类型（含2个已有技术支持类型）、114个关系类型；新增档案投影、授权、映射、规则/AI版本、来源贡献、事项阶段与参与、名单选择、审核轮次、内容确认、版本阅读和对接异常。
- 修正一人多个候选、一个标签多个推荐内容、一个人多个风险、跨批次作用标签等基数；接收记录按任务+人员稳定，版本阅读另建投影，原截止时间不因修订变化。
- 定义63个动作的输入签名、权限、前置条件、原子效果、幂等、事件和输出，独立ODL签名与YAML业务契约逐项对应。当前执行器不支持完整语义，均明确标记definition-only。
- 旧TransferAssignment示例保留但退出执行注册；原示例缺乏权威来源/人员归属校验且now为字面量，不能当作完整调动命令。当前runtime actions列表为空不等于没有动作定义，意味着尚未部署这些业务处理器。
- 增加规则、状态、12项指标口径、15项验收场景、试点附件4初始标签词表，以及需求书39项功能编号和3类试点扩展要求的覆盖索引。
- 明确阶段性首期范围、短信冲突、非对象标记权限、阅读率口径等决定；权威来源可替换，不假设现有明镜技术栈。
- `domain-pack/MIGRATION.md`说明关系基数、来源贡献、稳定接收记录、版本及历史快照的迁移要求；本次没有声称运行库或Java原型已迁移。

验证命令：`mvn -pl business-verification -am test`。包加载/关系表达性3项、契约一致性4项通过；其中需求覆盖测试验证编号和引用不漏项，业务场景文件仍是待执行契约，不是生产流程已验收。原有服务原型测试继续保留，不以其通过证明新契约已被执行。

## 2026-09-27：范围调整为核心价值大屏

用户将目标从完整业务系统调整为先验证核心业务价值。大屏围绕“对象—关系—画像—提醒—闭环”展示，数据使用明确标注的 Mock 数据。

### 实现

- 新增公开 `/dashboard` 入口，不要求登录，由 Spring Boot 同一 HTTP 服务提供 `dashboard.html`。
- 大屏展示有效对象、标签覆盖率、提醒任务、送达/阅读/逾期漏斗、组织分布、标签排行、数据质量和最近任务。
- 指标卡、组织、标签、逾期清单均可打开演示下钻，展示从总览数字回到对象明细的业务路径。
- 固定显示“演示数据 / Mock”和统计时间，页面不把演示数字伪装成生产统计。
- 采用 CSS/SVG 风格的无外部图表依赖展示，支持桌面和窄屏布局。
- 保留管理端人员目录和标签页面作为辅助入口；完整提醒审核、鹿路通生产闭环和 AI 执行暂停。

### 验证

- `npm --prefix web run build` 通过，生成管理端、核心价值大屏和接收端三个入口。
- `mvn -q -Dmaven.test.skip=true -pl mirror-server -am package` 通过，静态资源已复制进 Spring Boot JAR。
- 大屏 Playwright 测试通过：核心指标、Mock标识、逾期下钻、窄屏无横向溢出。
- 通过 `http://127.0.0.1:8080/dashboard` 验证后端直接返回大屏 HTML。

### 边界

Mock 数据只用于验证业务叙事、指标口径和页面信息架构，不代表真实人员或监督结果。真实 API、生产统计和完整提醒流程不在本轮大屏完成条件内。

### 补充验证

- 大屏增加显式加载状态和空数据状态，可通过 `?state=loading`、`?state=empty` 复现。
- 完整 Playwright 浏览器套件 8 项通过，包含大屏 2 项、人员目录 4 项、标签页面 2 项。

## 2026-09-26：M2首批标签配置与人工赋标

### 实现

- 新增真实标签API及React页面：最多三级目录创建、定义编辑和版本快照、启停、末级标签限制；停用分类时下级目录及生效人员标签同步失效，历史保留。
- 人员详情内可人工添加、删除、恢复并查看标签历史。界面按逻辑标签操作，保留原来源/来源组织，另行记录本次操作人和操作组织。
- 目录默认人工赋标，没有虚构规则或AI结果。单位和片区管理员只能在人员范围内操作，不能维护全局配置。
- 新增数据库功能权限表，目录查看、人员赋标、标签配置分别校验；服务端即时读取授权，撤销功能权限后已有会话写入也会拒绝。
- `BusinessCommands`通过同一Foundry事务提交变更、命令回执、审计和outbox。每租户乐观写入保护使并发配置/批量校验不静默覆盖，冲突返回409。
- 命令请求指纹规范化并绑定租户/账号/请求标识，同请求重试返回已保存结果，标识复用到其他请求会拒绝。重复有效添加不新造一次赋标历史。
- 批量API最多100人，逐人检查范围、当前组织、停用、非对象资格和预期版本；任一无效则整批回滚。批量选择界面和异步大批次仍待实现。
- 新增需求编号到页面/API/验收的对照表，明确每条需求的已实现子集与待补项。

### 实际验证

- 全仓库 `mvn -q test`：70项测试通过，无失败、错误或跳过。
- 标签HTTP/事务新增6项：人工生命周期与历史、幂等及旧版本冲突、功能与批量范围越权、批量回滚、目录层级与停用、并发同请求仅写入一次。
- 文件库应用重启测试扩展：重启后重放原赋标请求，仍只有一条初始标签历史。
- 前端生产构建通过；Playwright 6项通过（原4项＋真实API的标签配置/人工增删恢复历史、目录编辑与Escape关闭）。
